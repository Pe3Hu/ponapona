# Шаг 10. Три ограничения R1–R3

**Цель.** Заменить стабы пунктов 6–7 в `can_place` на реальные
ограничения R1, R2, R3. Ограничения активны всегда: мешок бесконечный,
эндгейма нет.

**Зависит от.** Шаг 9.

## Что уже есть (не дублировать)

- `BoardData.get_forced_spaces()` — базовый V-вырез, реализован на шаге 5.
- `BoardData.get_controlled_cells()` — две крайние клетки открытой дуги,
  реализован на шаге 5.
- `SandboxData.can_place` — пункты 1–5 (tile, free, neighbor, gold,
  forced priority). Пункты 6–7 — стабы `return true` с `# TODO step 10`.

Шаг 10 не переписывает эти методы, а **использует** их внутри R1–R3.

## Ограничение R1 — «три одинаковых цвета»

`SandboxData._creates_three_same_forced(cell_: Vector2i, tile_: HexTileData)
-> bool`:

1. Симулировать размещение `tile_` в `cell_` (без изменения доски):
   собрать `filled_after = board.filled | {cell_: true}` и
   `edges_after[d] = color на ребре (cell_+dir[d])→cell_`.
2. Для каждого `n` из 6 соседей `cell_`:
   - если `n` было пусто и `filled_after` даёт ровно 3 подряд соседа —
     `n` стало вырезом;
   - собрать 3 цвета, обращённых к `n` от соседей;
   - если все три совпадают — `return true`.
3. **Также** если `cell_` сам был вырезом до постановки (игрок
   заполняет вырез), проверить тот же пункт 2 — заполнение выреза
   может создавать **соседние** вырезы; если у соседа 3 одинаковых
   цвета — `return true`.
4. Иначе — `false`.

Кэш не нужен: обход O(6) на одну проверку.

## Ограничение R2 — «не окружать вырез четвёртым»

`SandboxData._is_fourth_neighbor_of_forced(cell_: Vector2i) -> bool`:

```gdscript
func _is_fourth_neighbor_of_forced(cell_: Vector2i) -> bool:
    for f in board.get_forced_spaces():
        for d in range(6):
            if f + Digest.hex_directions[d] == cell_:
                return true
    return false
```

Если `cell_` — сосед любого существующего выреза, постановка делает
вырез «4-сторонним». Запрещено.

Применяется только когда R5 не сработал (нет closable forced spaces).
Если closable вырез есть — игрок обязан играть в него, свободный ход
всё равно запрещён пунктом 5.

## Ограничение R3 — «контролируемые клетки»

`SandboxData._is_controlled_cell(cell_: Vector2i) -> bool`:

```gdscript
func _is_controlled_cell(cell_: Vector2i) -> bool:
    return cell_ in board.get_controlled_cells()
```

Если `cell_` — контролируемая клетка любого выреза — запрещено.
R2 и R3 частично пересекаются (обе запрещают открытую дугу выреза);
R3 ⊂ R2 на уровне «эта клетка запрещена». Это нормально: в правилах
Tantrix R2 и R3 разделены, потому что визуализируются по-разному.
В коде оба запрета работают независимо.

## Интеграция в can_place

Заменить пункты 6–7 стаба на:

```gdscript
# 6. R1: three same colors
if _creates_three_same_forced(cell_, tile_):
    return false
# 7. R2, R3: fourth neighbor / controlled cell
if _is_fourth_neighbor_of_forced(cell_):
    return false
if _is_controlled_cell(cell_):
    return false
```

Порядок: R5 (пункт 5) срабатывает раньше R1–R3 — если вырез closable,
игрок обязан в него. R1 проверяется для всех клеток (включая случай,
когда `cell_` уже вырез), R2 и R3 — для остальных свободных ходов.

## Отличие от настольной Tantrix

- В Tantrix R1–R3 действуют «пока в мешке есть тайлы» и снимаются
  в эндгейме. В песочнице мешок бесконечный, снятия нет.
- Игрок, если застрял, пользуется `apply_discard` (шаг 8) — сбросить
  тайл из руки и добрать новый. Это sandbox extension, не правило
  Tantrix.

## Что записать в `notes.md`

- R1 срабатывает и на «заполнение существующего выреза», если это
  создаёт соседний вырез с тремя одинаковыми цветами.
- R1–R3 активны всегда (эндгейма нет).
- R2 и R3 частично пересекаются (обе запрещают открытую дугу выреза);
  реализованы оба независимо, R3 ⊂ R2 на уровне «эта клетка
  запрещена».
- `apply_discard` — sandbox extension; в Tantrix его нет.
- Дедлок обрабатывается `apply_discard`, игра не заканчивается.
